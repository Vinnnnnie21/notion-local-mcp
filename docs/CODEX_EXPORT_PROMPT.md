# 任务：准备 notion 本机连接 mcp 的公开源码仓库

用户计划将自建 Linux MCP 的方法和代码开源到 GitHub，名称为“notion 本机连接 mcp”，建议仓库名 notion-local-mcp，原创代码和文档采用 MIT。项目拥有者和发布账号为 Vinnnnnie21，仓库为 Vinnnnnie21/notion-local-mcp。

本任务负责准备公开仓库，不改生产服务。已有文档准备包包含 README/LICENSE/SECURITY/CONTRIBUTING/.gitignore 和发布检查清单，先阅读并沿用。

## 环境

当前公开版本为 2.2.8-service-timeout-validation。每次更新前仍需核对实际源码版本。实际安装代码和私有维护目录受管理员路径保护，Notion 普通工具不能读取导出。你具备本机维护能力，但这不授权读取或输出任何 Token、签名私钥或业务凭据。

## 必须完成

1. 确认当前运行路径与代码版本，仅提取公开所需源码、测试、依赖说明；不复制整个安装目录、生产 config/state/backup/cache。
2. 在新独立目录生成候选公开仓库，不改原工作区或生产 app；不 reset/clean/stash 用户改动。
3. 检查所有 imports、入口和维护工具依赖，避免只导出主要文件而无法运行。
4. 去除个人用户、邮箱、真实项目、账号路径、服务器 IP/域名、生产日志、审批或候选状态、数据库、快照和制品。使用演示命名、用户自配置路径、仓库外私有状态。不要将硬编码秘密替换工作当作理由读取秘密。
5. 依据真实 schema 生成 config.example.json：无秘密、最小权限、精确演示项目、隔离默认启用、外网默认关闭。维护信任状态必须由新安装独立生成，不能复用生产签名材料或身份。
6. 提供环境预检、可复现安装步骤及可选用户 systemd 模板；验证 README 中命令和参数，不能编造“一键安装成功”。遇到 namespace/cgroup 不可用时明确失败，不宿主 Shell 回退。
7. 运行时与离线依赖不直接打包：提供合法来源、版本/摘要校验和准备方法，分别核对 Python/Node/PostgreSQL/Chromium 等许可证；不将第三方资产全部重授 MIT。
8. MIT 采用 Copyright (c) 2026 Vinnnnnie21。核查每个文件的权利与已有许可，保留第三方通知；不能因 AI 辅助编写就断言所有内容没有权利风险。
9. 完善 README 功能、架构、配置、连接、工具示例、超时/预算/UNKNOWN、隐私及局限。公开文档不得保留生产接入地址或测试任务 ID。
10. 扫描候选文件与拟提交 Git 内容，人工复核秘密、个人数据、第三方内容及不必要历史；扫描器不能保证识别全部秘密。
11. 在不含生产资源的干净 Linux 环境按 README 完成安装、认证 tools/list/call、文件/隔离/执行/浏览器/数据库/清理与负向验证。记录实际版本、测试数量和不足，不照搬原私有部署测试数。
12. 按真实测试结构建立 CI，不默认 hosted runner 的 namespace/systemd 权限足够。单元测试和 Linux 全功能集成测试分开，跳过项明确。
13. 根据结果更新文档发布状态，仍缺源码、配置或系统支持就明确标记，不伪装完成。

## 禁止

读取/复制/输出真实 Token、生产签名私钥、交易凭据；运行交易接口或修改交易系统；关闭认证；放开整机；将生产代码目录直接公开；自动 push 或将私有 Git 历史整体发布；删除原项目以获得干净状态。

## 交付

候选公开目录、文件清单、SHA256、版权/依赖核查结果、秘密与个人信息检查、干净环境安装和真实 MCP 验收记录、README 更新差异、尚未完成事项。
